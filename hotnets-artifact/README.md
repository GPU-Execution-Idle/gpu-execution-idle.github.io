# Wake the GPU: interactive companion

A mobile-first companion to the HotNets paper *“The Network Should Wake the GPU”*: three short,
self-paced activities. It is a static site (no build step, plain ES modules) on
GitHub Pages. There are no accounts and no backend: progress and each visitor's own Activity 2
attempts are stored only in their browser (`localStorage`).

```
web/                         ← deployed as-is to GitHub Pages
  index.html, styles.css
  shared/                    ← pure logic and data, no UI
    params.js                ← power / clock / recovery parameters (MEASURED vs PLACEHOLDER)
    activity0-data.js        ← Explore data: idle power (measured power + real executions from the L40S trace)
    activity0-traces.generated.js ← GENERATED by trace-analysis/extract_a0_examples.py
    activity1-data.js        ← Explore data: frequency settings, measured workload results, wake-up lead times
    scenarios.generated.js   ← GENERATED by trace-analysis/build_scenarios.py (Activity 2)
    activities.js            ← Activity 2 situations and latency budget
    sim.js                   ← Activity 2 simulation (energy saved, added latency)
  js/
    app.js                   ← hash router, activity navigation, progress bar, home
    store.js, progress.js    ← local storage; progress events for the navigation bar
    activities/explore.js     ← Explore session: page order, saved state, navigation, proposal page
    activities/explore-idle.js, explore-frequency.js ← Explore's pages (idle power / frequency)
    activities/activity2.js, runner.js ← Be the controller (Activity 2)
    ui/pager.js              ← shared Back/Next row
    ui/                      ← DOM helpers and SVG timelines
trace-analysis/              ← trace → data pipeline + TODOs (see trace-analysis/README.md)
tests/                       ← deno test --allow-read=. tests/
```

## Run locally

```bash
python3 -m http.server 8000 --bind 0.0.0.0 --directory web
# laptop: http://localhost:8000    phone on the same Wi-Fi: http://<laptop-ip>:8000
# (laptop IP on macOS: ipconfig getifaddr en0)
deno test --allow-read=. tests/           # simulation, causality and trace-data tests
```

## Deploy

This folder is part of the `gpu-execution-idle.github.io` repository; the workflow at the
repository root tests it and publishes `web/` at `/hotnets26-demo/` (see the root
README). Routes live in the URL hash (`#/explore`, `#/build`) and all asset paths are relative,
so the site works under any path and survives refreshes. Unknown routes (including old
`#/scoreboard`, `#/a0`–`#/a2` links) redirect to the right page.

## Model and honesty labels

- Idle power for the GPU picker in Activity 0 is **measured** (paper figure). Everything else about
  energy and latency is a **model estimate** (`web/shared/sim.js`) with placeholder parameters, labeled as such in the UI.
- Scenarios are **synthetic** until real traces are imported (`trace-analysis/README.md`).
- Predictors use only past observations, and the current call's duration stays hidden until the visitor
  locks in. The scenario file ships to the browser, so a determined visitor could read it; that's acceptable
  for a demo, not for anything adversarial.
- Model: the GPU sits in its chosen state from tool start until wake-up; wake-up (recovery) takes
  `R`; it then sits ready until the next inference. Wake-up begins at the predictive alarm
  (`predicted − R − margin`) or at tool completion, whichever comes first. Energy saved is
  relative to staying ready for the tool duration; added latency = inference start − tool end.
